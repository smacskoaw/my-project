# نتيجة التحقق المحلي والسحابي

تاريخ التحقق: 5 أكتوبر 2026.

## النسخة الحالية: GitHub Pages + Firebase

- تحوّل الموقع إلى Next.js static export؛ أُزيلت مسارات API من تطبيق الويب واستُبدلت باتصال Firebase للمتصفح.
- فُعّل Firebase Authentication للإدارة والزوار المجهولين، وحساب الإدارة مُنح claim موثوقاً. بقيت الفوترة غير مفعلة.
- نجحت اختبارات قواعد Firestore الخمسة: منع القراءة العامة، تقديم ذري صحيح، حظر القراءة والتعديل والحذف للمتقدم، رفض بيانات مزورة وحقول زائدة ومحاولات تجاوز قيد التكرار، والسماح لإدارة موثوقة بتغيير الحالة والحذف فقط.
- نجح بناء `out/` لمسار `/my-project` وفحص TypeScript. عولجت أسماء ملفات التحميل المسبق لتعمل دون إعادة كتابة روابط على الخادم.
- نجح فحص المتصفح للصور والخطوط والروابط والصفحات الداخلية والتحديث المباشر وعروض 390 و768 و1440 بكسل.
- نجح اختبار المتصفح مع Firebase الحقيقي من ملفات ثابتة: نموذج ومراجعة وموافقة وإرسال، دخول الإدارة، ظهور الطلب تلقائياً، البحث، تغيير الحالة، الحذف والخروج، ومنع الزائر من دخول الإدارة. حُذف طلب الاختبار وبقي الطلب الأصلي محفوظاً.
- قيود النسخة الحالية موثقة في README: قيد التقديم لكل هوية مجهولة وليس لكل هاتف أو IP، والإدارة تقرأ مجموعة الطلبات لحساب البحث والإحصاءات.

الأقسام التالية سجل لاختبارات نسخة الخادم السابقة، وليست وصفاً لطريقة تشغيل الموقع الحالية.

## التحقق من Firebase الحقيقي

- تم التحقق من قاعدة `(default)` في مشروع `sgyqkl`: إصدار Standard، وضع Native، والمنطقة `nam5`، و`freeTier=true`. الفوترة غير مفعّلة.
- نُشرت قواعد منع الوصول المباشر من العملاء والفهارس الخاصة بالتطبيق بنجاح.
- أُنشئت هوية خادم مخصصة بصلاحية `roles/datastore.user`؛ المفتاح داخل `.secrets/` وإعداد التشغيل داخل `.env.local`، وكلاهما مستثنى من Git.
- نُقل الطلب المحلي الموجود وحساب الإدارة إلى Firestore، مع الحفاظ على التواريخ والحالة وكلمة المرور المشفرة والنسخة المحلية.
- نجح اختبار HTTP على الموقع المتصل بالقاعدة الحقيقية: تسجيل دخول الإدارة، إرسال طلب تجريبي، ظهوره، البحث مع عدة فلاتر والترتيب بالاتجاهين، ثم حذف الطلب التجريبي وتسجيل الخروج. بقي الطلب الأصلي محفوظاً وعدّاده صحيحاً.
- رفضت قاعدة Firestore الحقيقية قراءة الطلبات دون تفويض: HTTP 403.
- الموقع يعمل محلياً مع قاعدة سحابية؛ لم يُنشر خادم الموقع على رابط عام بعد. يلزم إعداد أسرار الخادم على الاستضافة عند النشر.

## تحديث دعم Firebase

- أُضيف مصدر Firestore اختياري مع المحافظة على قاعدة PostgreSQL المحلية الحالية.
- `npm test`: 11 اختباراً ناجحاً، بما فيها بحث Firestore وتوحيد الهاتف.
- `npm run test:firestore`: 7 نتائج ناجحة (مجموعة رئيسية و6 سيناريوهات) على محاكي رسمي ومشروع وهمي. شملت منع تكرار المعاملات المتزامنة، العدادات، الفلاتر، الحذف، الجلسات، وحدود المحاولات.
- رفض محاكي Firestore قراءة وكتابة وثائق المتقدمين وقراءة حسابات الإدارة من REST دون صلاحيات: HTTP 403.
- `npm run test:e2e:firestore`: نجحت اختبارات المتصفح الثلاثة للتقديم والإدارة وتوافق الشاشات باستخدام Firestore المحاكية.
- `npm run test:e2e`: نجحت اختبارات المتصفح الثلاثة مجدداً باستخدام PostgreSQL، للتأكد من بقاء المسار المحلي سليماً.
- `npm run build` وفحص TypeScript: نجحا بعد إضافة Firebase.
- `npm audit --omit=dev`: لم يظهر أي تنبيه أمني في حزم التشغيل بعد إصلاح اعتماد uuid. لدى Firebase CLI، وهي أداة تطوير، تنبيهات في اعتمادياتها؛ لم نطبّق تخفيض إصدار قسرياً، ويزيل إعداد نشر Render حزم التطوير بعد البناء.
- المحاكي لا يفرض الفهارس المركبة كما تفعل خدمة Firestore الحقيقية؛ لذلك أُجري أيضاً التحقق السحابي الموضح أعلاه.

## التحقق السابق عند الإنشاء

- `npm run build`: نجح بناء الإنتاج، بما فيه فحص TypeScript.
- `npm test`: نجحت الاختبارات التسعة للتحقق من البيانات، وتوحيد الهواتف، والموافقة، وكلمات المرور، وفحص المصدر، وحد حجم الطلب، والحفظ الدائم وقيود القاعدة والتعديل والحذف.
- `npm run test:e2e`: نجحت اختبارات المتصفح الثلاثة عبر Edge.
- التقديم والمراجعة والتعديل والحفظ والموافقة الإلزامية ومنع التكرار: اختُبرت فعلياً.
- الدخول الخاطئ والصحيح، جلسة HttpOnly وSameSite، وحظر قراءة وتعديل الطلبات دون دخول: اختُبرت فعلياً.
- البحث بالاسم وبالهاتف بصيغة محلية وأرقام عربية، الفلاتر، الصفحات، التفاصيل، الحالة، الحذف وتسجيل الخروج: اختُبرت فعلياً.
- روابط واتساب: تم التحقق من الرقم الدولي والرسالة في الرابط، دون إرسال رسائل خارجية.
- أحجام 390 و768 و1440 بكسل: لا يوجد تمرير أفقي؛ حُفظت صور الصفحة الرئيسية. اختُبرت الإدارة على الهاتف والكمبيوتر أيضاً.
- كل البيانات التجريبية وحساب الاختبار داخل `.test-data/e2e` المعزولة فقط.

الصور متاحة بعد الاختبارات في `test-results/home-390.png` و`home-768.png` و`home-1440.png` و`admin-mobile.png` و`admin-desktop.png`.

لم يُنشر الموقع على دومين عام. اختُبر مسار قاعدة البيانات على PostgreSQL المدمجة PGlite، ولم يُختبر اتصال PostgreSQL خارجية أو شهادات TLS للاستضافة لعدم توفير إعداداتها. يتطلب الإنتاج تعيين المتغيرات وإنشاء حساب الإدارة وإجراء تحقق بعد النشر كما في README.
