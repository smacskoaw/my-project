# Firebase مع GitHub Pages

الموقع الحالي ثابت. يستخدم Firebase Authentication وCloud Firestore مباشرة، دون Render أو Functions أو App Hosting أو ربط فوترة.

## الإعداد المطبق

- المشروع `sgyqkl` وقاعدة `(default)` من نوع Standard/Native على Spark.
- تفعيل Email/Password للإدارة وAnonymous لتقديم الزوار.
- السماح بالنطاق `smacskoaw.github.io` ونطاقات التطوير المحلية.
- حساب الإدارة في Firebase Auth له claim `minassatiAdmin: true`. البريد الداخلي للحساب ليس صندوق مراسلة؛ استعادة كلمة المرور تكون من مسؤول مشروع Firebase، وليس عبر إرسال بريد إليه.
- طلبات الموقع في `minassati_applications`. قيد التكرار وإيصالات غير حساسة في `minassati_submitters`.
- كل مجموعات الخادم السابقة مثل `minassati_admins` و`minassati_sessions` محجوبة عن المتصفح.

## نشر القواعد والإعداد

```sh
npx firebase login
npx firebase deploy --only auth,firestore:rules --project sgyqkl
```

لا تنشر قواعد اختبار مفتوحة. `npm run test:rules` يفحص قواعد التقديم والإدارة في المحاكي قبل النشر.

## إدارة الحساب

المستخدم العادي أو حساب البريد المسجل حديثاً لا يملك صلاحية الإدارة. إنشاء حساب جديد لا يمنحه claim. عند إضافة مسؤول جديد، ينشئ مالك المشروع حساب Email/Password ثم يمنحه `minassatiAdmin: true` بواسطة Admin SDK عبر اعتماد إداري موثوق خارج المتصفح. لا تضع مفاتيح خدمة أو كلمات مرور في JavaScript أو GitHub Secrets لبناء الموقع؛ البناء لا يحتاجها.

حساب الخدمة المحلي القديم مخصص لأدوات الصيانة والترحيل فقط، ولا يستخدمه الموقع المنشور. حساب الإدارة القديم المشفر حُفظ أثناء الترحيل، لكن تسجيل الدخول الحالي يتم بواسطة Firebase Auth.

## حدود التشغيل المجاني

القراءة والإرسال يستهلكان حصة Firestore. الإدارة تقرأ مجموعة الطلبات وتتابع التغييرات، وتنفذ البحث والتصفية داخل جلسة المسؤول فقط. لا تفعّل فوترة تلقائياً. قيد التقديم يمنع التكرار السريع لنفس الهوية المجهولة؛ ليس حاجزاً شاملاً أمام الروبوتات أو الأرقام المكررة من أجهزة أخرى.
