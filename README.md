# منصتي

موقع عربي لاستقبال طلبات التوظيف في العراق وسوريا. يعمل على **GitHub Pages + Firebase**، بدون خادم Next.js أو Render.

- الموقع: https://smacskoaw.github.io/my-project/
- الإدارة: https://smacskoaw.github.io/my-project/admin/
- قاعدة البيانات: Cloud Firestore في مشروع `sgyqkl`.

## طريقة التشغيل

`npm run dev` للمعاينة المحلية. يحتاج Node.js 24.

لبناء نسخة GitHub Pages في PowerShell:

```powershell
$env:NEXT_PUBLIC_BASE_PATH='/my-project'
npm run build
npm start
```

افتح `http://localhost:4173/my-project/`. ينتج البناء مجلد `out/` فقط، ولا يحتاج الموقع المنشور إلى ملفات البيئة أو مفاتيح حساب خدمة.

## النشر

الملف `.github/workflows/pages.yml` يبني الموقع وينشر `out/` عند رفع تغييرات إلى `main`. إعداد GitHub Pages هو **GitHub Actions**. ملف `.nojekyll` يتيح ملفات Next؛ وخطوة `finalize-static.mjs` توفر أسماء ملفات تحميل أجزاء الصفحات التي تطلبها واجهة Next على الاستضافة الثابتة.

لا يكفي نشر ملفات المصدر أو README؛ ما يُنشر هو ناتج البناء. عند تغيير اسم المستودع، حدّث `NEXT_PUBLIC_BASE_PATH` في سير النشر.

## Firebase وحماية البيانات

- بيانات إعداد تطبيق الويب في `src/lib/firebase-client.ts` عامة وليست مفتاح إدارة.
- يدخل المسؤول عبر Firebase Authentication. اسم المستخدم يُحوّل إلى عنوان داخلي في نطاق `admin.sgyqkl.firebaseapp.com`؛ الصلاحية لا تعتمد على الاسم أو البريد، بل على claim موثوق `minassatiAdmin: true` يعيّنه مسؤول المشروع.
- المتقدم يحصل على هوية Firebase مجهولة عند الإرسال فقط. لا يستطيع قراءة الطلبات أو تغييرها أو حذفها.
- قواعد `firestore.rules` تتحقق من الحقول والأطوال والوقت وحالة الطلب وتُلزم إرسال الطلب وإيصال الاستلام وقيد التكرار في عملية واحدة.
- يوجد فاصل عشر دقائق لكل هوية متصفح. هذه ليست حماية لكل رقم هاتف أو عنوان IP؛ مسح تخزين المتصفح أو استخدام هوية جديدة قد يتجاوز هذا الفاصل. Firebase يطبق أيضاً حدود إنشاء حسابات ومحاولات دخول.
- لا تحفظ الواجهة كلمة مرور المسؤول. جلسة الإدارة ضمن جلسة المتصفح، ولا يوجد حساب افتراضي منشور في المصدر.
- لوحة الإدارة تتلقى الطلبات مباشرة، وتحسب الإحصاءات والبحث والصفحات محلياً بعد تفويض القراءة. عند فتح الإدارة تُقرأ مجموعة الطلبات؛ للبيانات الكبيرة يلزم تطوير استعلامات وصفحات خادمية لتقليل استهلاك القراءة.
- الخطة الحالية Spark دون فوترة؛ الاستخدام خاضع لحصص Firebase المجانية.

## الاختبارات

```sh
npm test
npm run test:rules
npm run test:e2e
```

اختبارات القواعد تعمل في محاكي معزول `demo-minassati` وتحتاج Java 21. اختبار المتصفح يفحص نسخة `out/` المبنية مسبقاً لمسار `/my-project`؛ يستخدم Edge على Windows، أو عيّن `BROWSER_PATH` لمتصفح Chromium.

اختبارات الخادم القديمة في `tests/e2e/` و`tests/firestore/` توثق النسخة السابقة ولا تمثل مسار النشر الحالي. أدوات PostgreSQL وحسابات الخادم القديمة باقية للترحيل فقط؛ لا تُستخدم في الموقع الثابت.

## الحفاظ على البيانات

الطلب السابق محفوظ في Firestore، والنسخة المحلية في `data/minassati` باقية. لا تحذفها دون نسخة احتياطية. لا ترفع `.secrets/` أو `.env.local` أو بيانات المتقدمين إلى GitHub. بيانات الطلبات لا تدخل في ملفات البناء.

راجع [إعداد Firebase](docs/firebase-setup.md) و[نتائج التحقق](docs/verification.md).
