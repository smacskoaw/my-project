# منصتي

منصة عربية RTL لاستقبال طلبات التوظيف في العراق وسوريا، مع نموذج تقديم، مراجعة قبل الإرسال، ولوحة إدارة خاصة. مبنية باستخدام Next.js App Router وReact وTypeScript وCSS متجاوب. الصور والخطوط محلية، ولا يحتاج الموقع إلى خدمات صور أو خطوط خارجية أثناء الاستخدام.

## Firebase والنشر المجاني

أُضيف دعم **Cloud Firestore** لمشروع `sgyqkl`، مع الحفاظ على PostgreSQL للتطوير والبيانات الحالية. اختر المصدر عبر `DATABASE_PROVIDER=firestore` أو `postgres`. إعداد متصفح Firebase وحده لا يمنح الخادم صلاحية الوصول، ولا يفعّل الحفظ السحابي تلقائياً.

راجع [دليل Firebase والنشر المجاني](docs/firebase-setup.md) لإنشاء القاعدة، وضبط صلاحية الخادم، وإنشاء حساب الإدارة، ونشر قواعد الحماية والفهارس. يجهز `render.yaml` خدمة Next.js على خطة Render المجانية تستخدم Firestore على Spark؛ لا ينشئ خدمة مدفوعة أو حساب فوترة. لا يستخدم المشروع Firebase App Hosting أو Cloud Functions أو Storage.

حساب الإدارة المحلي والطلبات المحلية لا تنتقل تلقائياً عند تبديل مصدر البيانات. لا تحذف `data/minassati`؛ أنشئ حساب الإدارة في المصدر الجديد قبل استخدامه. الترحيل إلى القاعدة السحابية خطوة منفصلة. الخطوات التالية الخاصة بـPostgreSQL تبقى صالحة عند اختيار `DATABASE_PROVIDER=postgres`.

## المتطلبات والتشغيل

- Node.js 24 LTS وnpm.
- للتطوير: PostgreSQL مدمجة عبر PGlite تحفظ البيانات فعلياً في `data/minassati`.
- للإنتاج: Firestore مع صلاحية خادم أو PostgreSQL مستقلة، ورابط HTTPS.

```bash
npm ci
```

انسخ `.env.example` إلى `.env.local` واضبط `APP_ORIGIN=http://localhost:3000`، ثم:

```bash
npm run dev
```

افتح `http://localhost:3000`. رابط الإدارة: `http://localhost:3000/admin`.

إذا لم يكن Node مثبتاً على هذا الجهاز، توجد نسخة محلية ضمن `.tools/node-v24.12.0-win-x64` أُضيفت أثناء التطوير. لا تُرفع هذه الأدوات إلى السيرفر. يمكن تشغيلها في PowerShell:

```powershell
$env:PATH = (Join-Path $PWD '.tools\node-v24.12.0-win-x64') + ';' + $env:PATH
npm.cmd run dev
```

## إنشاء حساب الإدارة

أوقف خادم التطوير قبل استخدام أدوات قاعدة PGlite؛ لا تشغّل أكثر من عملية على مجلدها في الوقت نفسه. عيّن مؤقتاً في `.env.local`:

```dotenv
ADMIN_USERNAME=your-admin-name
ADMIN_PASSWORD=your-own-long-random-password
```

الحد الأدنى لكلمة المرور 8 محارف، ويُفضّل اختيار كلمة عشوائية من 14 محرفاً أو أكثر، ثم:

```bash
npm run admin:create
```

أزل `ADMIN_PASSWORD` من ملف البيئة بعد الإنشاء. تكرار الأمر باسم مستخدم قائم يغيّر كلمة مروره ويلغي جميع جلساته. لا يوجد حساب إدارة افتراضي أو كلمة مرور داخل واجهة الموقع. تُخزّن كلمات المرور باستخدام scrypt وملح عشوائي، وتُخزّن تجزئة رمز الجلسة فقط في قاعدة البيانات. مدة الجلسة 8 ساعات.

## ربط PostgreSQL

ضع رابط قاعدة البيانات في متغير الخادم `DATABASE_URL`:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=verify-full
```

استخدم إعداد TLS والشهادة الموصى بهما من مزوّدك؛ لا تعطّل التحقق من الشهادة. تُنشأ الجداول والفهارس من `database/schema.sql` عند أول اتصال. تحتاج عملية التهيئة لصلاحية إنشاء الجداول. يمكن لمسؤول قاعدة البيانات تنفيذ الملف مسبقاً. لا تُنقل البيانات تلقائياً من قاعدة التطوير إلى الإنتاج. لا تستخدم قاعدة التطوير لتخزين بيانات متقدمين حقيقية على جهاز مشترك.

PGlite قاعدة PostgreSQL محلية دائمة وليست مصفوفة وهمية؛ لكنها مخصصة هنا للتطوير بعملية واحدة. يشترط الكود وجود `DATABASE_URL` في الإنتاج ويستخدم pool للاتصالات. جميع نسخ التطبيق في الإنتاج تشترك في PostgreSQL واحدة، بما فيها الجلسات وحدود المحاولات.

## النشر على سيرفر

1. أنشئ PostgreSQL منفصلة، واضبط النسخ الاحتياطي وفق سياسة الجهة المشغلة.
2. انقل المشروع وثبّت الحزم باستخدام `npm ci`.
3. اضبط المتغيرات في بيئة السيرفر، ولا تضعها في ملفات عامة أو متغيرات تبدأ بـ `NEXT_PUBLIC_`:

```dotenv
DATABASE_URL=your-production-postgresql-url
APP_ORIGIN=https://your-domain.example
COOKIE_SECURE=true
TRUST_PROXY=true
RATE_LIMIT_SECRET=your-random-secret-at-least-32-characters
```

لإنشاء السر محلياً:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

4. أنشئ حساب الإدارة بالأمر السابق مع قاعدة الإنتاج.
5. ابنِ وشغّل:

```bash
npm run build
npm start -- --hostname 127.0.0.1
```

6. استخدم process manager مثل systemd لإعادة التشغيل، ووكيل HTTPS مثل Nginx. يوضح `deploy/nginx.conf` إعداد الوكيل. ضع شهادتك ودومينك الفعليين، ثم وجّه DNS إلى السيرفر. لا تكشف منفذ Next.js مباشرة للإنترنت؛ الوكيل يجب أن **يستبدل** `X-Real-IP` بعنوان العميل. لا تفعّل `TRUST_PROXY` إذا لم تضمن ذلك. في الوضع المحلي دون الوكيل تستخدم الطلبات مجموعة حد محاولات مشتركة.
7. نفّذ تحققاً بعد النشر: تقديم طلب، مراجعته، دخول الإدارة، تغيير حالته، ثم حذفه. يجب اختبار النشر مع PostgreSQL الفعلية وTLS قبل استقبال بيانات حقيقية.

مثال لصيانة يومية من أداة PostgreSQL موثوقة:

```sql
DELETE FROM sessions WHERE expires_at < NOW();
DELETE FROM rate_limits WHERE reset_at < NOW() - INTERVAL '1 day';
```

هذه الأوامر تحذف الجلسات وحدود المحاولات المنتهية فقط. احتفظ بنسخ احتياطية مشفرة خارج السيرفر واختبر استعادتها. تحدد الجهة المشغلة مدة الاحتفاظ بالطلبات وصلاحيات موظفيها. حدّث سياسة الخصوصية ببيانات الجهة ووسيلة اتصال مباشرة قبل الإطلاق العام.

## الميزات

- حقول شخصية ومهنية كاملة، مع تخصص «أخرى» ومؤهلات ومهن متعددة.
- تحقق مشترك في المتصفح والخادم، وأرقام دولية مع دعم الأرقام العربية.
- مراجعة وتعديل دون ضياع البيانات خلال جلسة التبويب؛ تُمسح المسودة بعد الإرسال.
- موافقة إلزامية تُسجل مع وقت التقديم.
- UUID لكل طلب ومفتاح idempotency يمنع تكرار نفس الإرسال عند إعادة المحاولة.
- طلب واحد لكل رقم خلال 10 دقائق، و20 محاولة تقديم لكل عنوان خلال 10 دقائق؛ تسجيل الدخول محدود بـ10 محاولات لكل عنوان ولكل اسم مستخدم خلال المدة نفسها.
- لوحة إدارة: إحصاءات حقيقية، بحث بالاسم والهاتف، جنسية ومدينة ومؤهل وتخصص وحالة، ترتيب، وترقيم صفحات (12 طلباً للصفحة).
- تفاصيل كاملة، حالات ملونة، واتساب برقم دولي ورسالة مشفرة، وحذف مؤكد من القاعدة.
- معالجة الأخطاء، حالات تحميل، إشعارات، دعم لوحة المفاتيح وتقليل الحركة.

## الأمان

قراءة الطلبات وتعديلها وحذفها تتطلب جلسة إدارة صالحة على الخادم. جميع عمليات التغيير تتحقق من `Origin`، والجلسات `HttpOnly` و`SameSite=Strict` و`Secure` عند تفعيل HTTPS. استعلامات قاعدة البيانات مُعلّمة بالمعاملات، والواجهة تعرض النصوص باستخدام escaping الافتراضي في React. يُرفض JSON أكبر من 20KB. لا تُطبع بيانات المتقدمين أو كلمات المرور في سجلات التطبيق. تضبط Next.js رؤوس حماية المحتوى والإطارات ونوع المحتوى. لا يوجد مسار عام لعرض الطلبات أو استرجاعها برقم الهاتف.

## الاختبارات

```bash
npm run typecheck
npm test
npm run build
npx playwright test
```

اختبارات الوحدة تختبر التحقق، الأرقام، الموافقة، روابط واتساب، والحفظ الدائم وقيود القاعدة. اختبارات المتصفح تُنشئ قاعدة **معزولة** تحت `.test-data/e2e` وتستخدم بيانات وحساباً تجريبيين فيها فقط. تقوم بتهيئة هذه القاعدة عند كل تشغيل؛ لا تستخدم هذا المسار لبياناتك. تُختبر رحلة التقديم والتعديل والموافقة والإرسال، الدخول الخاطئ والصحيح، حظر الوصول العام، الفلاتر، الصفحات، الحالة، الحذف، واتساب، وتسجيل الخروج. صور الواجهات تحفظ في `test-results`.

الإعداد الافتراضي لاختبارات المتصفح يستخدم Edge على Windows. على نظام آخر اضبط `BROWSER_PATH` على مسار Chromium/Chrome المثبت. أوقف أي خادم على المنفذ 3000 قبل تشغيل الاختبارات، فالتشغيل الآلي يستخدم خادماً معزولاً. لا تتصل اختبارات المتصفح بخدمة واتساب؛ تتحقق من الرابط فقط.

## بنية المشروع والتعديل

```text
src/app/                  الصفحات ومسارات API والتنسيق العام
src/components/           النموذج، المراجعة، الإدارة، عناصر الهوية
src/lib/constants.ts      القوائم وأسماء الحقول والحالات والمدن
src/lib/validation.ts     قواعد التحقق وتوحيد أرقام الهاتف
src/lib/db.ts             اتصال PostgreSQL / PGlite
src/lib/security.ts       الجلسات، كلمات المرور، المصدر، حدود المحاولات
src/lib/applications.ts   البحث والإحصاءات وترقيم الصفحات
database/schema.sql       مخطط قاعدة البيانات
scripts/create-admin.ts   إنشاء الإدارة وتغيير كلمة المرور
public/images/            رسومات SVG محلية قابلة للتعديل
public/fonts/             خط Vazirmatn ورخصة OFL
tests/                    اختبارات الوحدة وقاعدة البيانات والمتصفح
deploy/                   إعداد الوكيل للنشر
```

لتغيير النصوص الرئيسية عدّل `src/app/page.tsx`، وللهوية والألوان `src/app/globals.css` و`src/components/site-shell.tsx`. عدّل القوائم في `constants.ts`. عند تغيير حقول الطلب، حدّث قواعد التحقق والنموذج وعرض التفاصيل والاختبارات معاً. تغييرات مخطط قاعدة البيانات المستقبلية تحتاج migrations مراجَعة؛ لا يكفي `CREATE TABLE IF NOT EXISTS` لتعديل الجداول القائمة.

المراجع التقنية: [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)، [إدارة Cookies](https://nextjs.org/docs/app/api-reference/functions/cookies)، [Node.js](https://nodejs.org/en/download).
